haql-qc · Data quality

Your summary adds up. That's the problem.

Totals hide contradictions. A production file can balance perfectly while four wells carry negative water volumes and a shut-in well quietly produces all month. haql-qc is the second pair of eyes that never gets tired — it reads every row, names every contradiction, and hands you a row number instead of a hunch.

# get the binary — Windows .exe, macOS, or Linux (no Python)

# audit a production export
haql-qc -i production.csv \
         --well-column WELL_BORE_CODE \
         --date-column DATEPRD \
         --declare-unit BORE_OIL_VOL=Sm3 \
         --declare-unit BORE_GAS_VOL=Sm3 \
         --declare-unit BORE_WAT_VOL=Sm3 \
         -r audit.json

Every run also records the SHA-256 of the exact input, so anyone can re-verify the audit against the same bytes later — and --attest --sign-key seed.key signs the report (Ed25519 over the file hash and a root over every finding) so the audit can be handed over provably unedited.

What it is

A deterministic QC pass over the export you already have.

No database, no login, no pipeline to set up. A CSV in, an audit report out. The rules are permanent numbered IDs, so a finding you saw in March is the same rule with the same name in December.

Goes in

Production CSV — daily or monthly period. Well and date columns identified. Units declared by you, never guessed from a column name.

Comes out

JSON or JSONL audit report: findings by rule and severity, per-well medians used for materiality, and the run-level SHA-256 of the exact input so the run can be re-checked against the same bytes.

On regulators and filings. haql-qc does not generate regulator-specific forms, and it does not know any state's format. It checks the volumes those forms are built from — and it is jurisdiction-agnostic, whether your wells are in Texas, Alberta, or the North Sea.

Why you need it

Scanning fifteen thousand rows is not a review. It's a hope.

Every one of these is a real failure mode. Each one has already cost someone a rejected filing, a partner dispute, or a late night re-keying numbers.

The filing is rejected

A monthly state filing is a legal document built on volumes. A wrong disposition code or a missed stock change gets it rejected — and you resubmit, late.

The partner dispute

A joint-venture partner queries a volume. You pull the export. You cannot establish which figure was right on the day it was received, because the correction was made on a guess and the trail is gone.

The silent pass

Row thirteen thousand looks exactly like a correct row when you are scanning. It is a negative water volume, and the summary total still adds up — because a total does not care about signs.

The month-end scramble

Mismatches surface in the last two days. Someone is re-keying numbers at 9pm, and the person doing it is not the person who will defend the number in April.

Without haql-qc

A month closes. The export looks complete. Nothing in the summary flags a problem, because the summary is a total and the total still adds up.

Four wells carried negative water volumes. The largest was −457.84 Sm³.

→

With haql-qc

Four rows are named — well, date, line number, observed value, unit. An engineer decides whether the sign convention or the meter failed.

Either way it never reaches a filing, and the report records the SHA-256 of the exact input audited.

What it actually catches

Missing, negative, contradictory, impossible.

The full check list
  • Missing or unparseable identifiers — a row that cannot be attributed to a well
  • Negative production volumes — not realisable; flagged whether produced or injected, because the sign convention differs
  • Cumulative totals that decrease — impossible without a documented reset
  • Shut-in contradictions — zero uptime while still producing at normal rate
  • Date gaps — a gap beyond the well's own cadence, where that cadence is inferred from that well's own history, not assumed globally
  • Plausibility breaches — a daily rate above the fixed per-fluid ceiling (oil 200,000 bbl/d, water 500,000 bbl/d, gas 5,000,000 MCF/d default; overridable), not performance judgements
  • Signed audit — --attest --sign-key seed.key attaches an Ed25519 attestation over the report hash together with a root hash covering every finding, so a single edited finding breaks verification; --bundle out.zip packs report + attestation into a byte-reproducible zip for transmission

Materiality is measured against the well's own median. 0.003 Sm³ is nothing on a well producing 6,000 Sm³/d and an emergency on one producing 5.
