The cost

A volume error does not stay an error.

It gets filed. It gets reported to a partner. It gets netted against a royalty owner who did not agree. By the time someone catches it, the correction is a letter, an amended report, and a reconciliation meeting.

The filing is rejected

A monthly state filing is a legal document built on volumes. A wrong disposition code or a missed stock change gets it rejected — and you resubmit, late.

The partner dispute

A joint-venture partner queries a volume. You pull the export. You cannot establish which figure was right on the day it was received, because the correction was made on a guess and the trail is gone.

The month-end scramble

Mismatches surface in the last two days. Now someone is re-keying numbers at 9pm, and the person doing it is not the person who will defend the number in April.

The silent pass

How it works

One step added. Nothing replaced.

  1. ExportProduction, monitoring or MRV data from whatever you already use — no change to your capture or accounting system.
  2. Send or runRun the CLI yourself, or email the file for a free sample check — two separate paths, both using the same rules.
  3. ReviewEvery finding names the rule, the well, the date and the row. Open the CSV and look.
  4. FixYou correct your source of truth. The tool never writes to your file.
  5. File or closeWith a report that shows what was checked and what was found.
Same rules every time

Deterministic on findings. Identical input bytes and configuration produce identical findings; the embedded run timestamps vary, the findings do not.

Every finding cites its row

Rule ID, 1-indexed source row, observed value, and the input SHA-256. "There was a problem" is not actionable; a row number is.

Runs offline

No network call, no telemetry, no upload. Reservoir data frequently cannot leave your infrastructure, so the tool never asks it to.

It says when it does not know

No unit declared means no unit-dependent check runs, and the report names the gap. It will not guess and put a false claim in the audit record.

About Haql Labs

Why you should hand over a month of data to a stranger.

Fair question. Here is the actual answer.

Every Haql Labs package installs the full source locally, so the code that touches your file is on your machine where you can read it before you run it. The rules are numbered permanently: adding a rule never renumbers an existing one, because audit logs referencing them are already in other people's hands.

  • Never corrupt source data. The tools are read-only by construction. They cannot auto-correct, because correcting requires knowing which of two contradictory fields is wrong, and the data cannot supply that.
  • Never guess. A confidently wrong unit is worse than no check at all. Units are declared by you and recorded in the report as your declaration.
  • Never be untraceable. Every finding ties to a stable rule ID, a row you can open in an editor, and a hash of the input.

Validation of haql-qc is against one public field — Volve, 15,634 daily rows and 526 monthly rows. One field is a starting point, not a general guarantee, and we will not claim otherwise.

FAQ

Straight answers.

Does it use AI?

No. Every rule is deterministic arithmetic on your data — comparisons, monotonicity checks, medians. No model, no network call, no language model anywhere in the packages. Running the same file twice gives the same answer.

Does my data leave my computer?

Run locally, nothing leaves your machine — the code makes no outbound calls. If you use the free sample check instead, you are choosing to email us the file, and you can ask for it back anonymised or deleted.

What do I need to install?

Nothing, if you use the free sample check. To run the tools yourself you need Python 3.9 or newer and nothing else; the audit engine is standard library only.

Which product do I need?

QC for the daily or monthly export you already have; closeout when the period needs to be locked; haql-45q if you report carbon capture and storage. Units and Coords are free libraries you use from your own code.

Can I try it free?

Yes. Email one month of data — anonymised if you prefer — and you get the full report at no cost. Evaluation use of the CLI also needs no license key.

How is it licensed?

haql-qc, haql-closeout and haql-45q are proprietary: running them commercially requires a license. Licenses are signed ed25519 tokens carrying company, tier, seats and expiry, verified entirely offline against an embedded public key — no activation server, no phone-home. haql-units and haql-coords are MIT and need no license at all.

Will it decide whether my well is performing?

No. Plausibility is not performance. It flags a rate above the configured plausibility ceiling — not because the rate is unusual, but because it cannot be real in your facility. It refuses questions outside its competence.

Is a revoked license still verified offline — why?

Because nothing inside the token records that fact. A revoked license verifies correctly until it expires, unless the caller checks a registry. We would rather state that limit than imply revocation works offline when it does not.
