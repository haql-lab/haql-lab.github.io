haql-engine · decision guide

Evidence is not a decision. Make the decision inspectable.

An audit can say whether a run reproduces and conserves. A decision needs more: where the runs separate, what residual risk is being accepted, who owns it, and what the field actually looks like. These three layers make that record visible.

Second opinion: find the first disagreement, not just the verdict

The normal audit compares a delivered run with a reference you supply. The second-opinion path supplies the reference itself: it re-runs the same deck with OPM Flow on this machine, instruments only the output balance vectors, and audits the delivered run against that independent reproduction.

python3 verify/secondopinion.py \
  --deck CASE.DATA --run delivered/ \
  --workdir /tmp/case-opm \
  --out secondopinion.md --json secondopinion.json

The useful output is not a single pass/fail. It is the earliest matched report step where pressure or saturation fails the pre-registered gate, the worst active cell and its (I,J,K), both values, and the same-cell phase state. That is where an engineer starts looking.

Schedule-aware. A calendar date is compared only when both summaries record the same elapsed TIME. If a reference was generated with a different TSTEP/DATES schedule, the tool skips the mismatched pairs and reports them instead of calling a timestep difference a model difference. If no pair shares an elapsed time, it stops rather than pretending the comparison is valid.

A hypothesis is labelled as a hypothesis. The tool can say the candidate puts gas where the reference has none; it does not claim that RS/PB is the proven root cause. The engineer tests it.

Decision Risk Ledger: record the risk you are accepting

The ledger is a decision record, not a reserves certification. It records the decision, its materiality, the evidence records, residual risks, owners, conditions and review triggers. Every evidence file is SHA-256-pinned, and the ledger has a content-derived record ID.

python3 verify/ledger.py --config decision.json \
  --out ledger.md --json ledger.json
python3 verify/ledger.py --verify-ledger ledger.json

--verify-ledger re-hashes the evidence and checks the ledger's own record ID. A changed evidence file, a missing file, or a hand-edited record is detected. The hash is tamper-evident, not a signature: a writer who can change both the evidence and the ledger can recompute it. For a signed decision, use the organisation's signing process.

RecordQuestion it answers
Decision and ownerWhat was decided, by whom, and when?
MaterialityWhat error would change the decision?
EvidenceWhich audit, Model CI and second-opinion records support it, and have they changed?
Residual riskWhat remains uncertain, who owns it, how is it mitigated, and what trigger forces a review?
ConditionsWhat must be closed before the decision is unconditional?

Not a certification. The ledger does not judge geology, upscaling, history match or reserves. It makes the decision and its accepted uncertainty inspectable years later. A high-severity audit finding can be recorded, but it cannot be made to disappear by writing a ledger.

Field maps: see where the state is changing

Summary curves show the wells; they do not show the field. run_spe1.py --save-fields records pressure, water saturation, gas saturation and dissolved gas ratio in a self-describing compressed NPZ. plot_fields.py renders layer maps and x/y cross-sections, and exports a ParaView-readable structured grid.

python3 run_spe1.py --T 3285 --save-fields --fields-every 10 \
  --json run.json --fields-file run_fields.npz
python3 plot_fields.py run_fields.npz \
  --time 3285 --layer 3 --section x --index 5 \
  --out fields.png --vtk fields.vts

The plot is two rows: pressure, Sw, Sg and So layer maps on top; cross-sections below. --time selects the nearest stored snapshot; --layer is 1-based in the solver's k-major order. The VTK file carries pressure, sw, sg, so, rs and TIME as point data, with no VTK Python package required.

Plotting is post-processing. The solver core does not import matplotlib, and a run does not need plotting installed.

How to check it

# second opinion and ledger regressions
python3 verify/tests.py

# field snapshots, maps, cross-sections and VTK
cd engine
python3 -m unittest -v test_fields

# the complete engine suite
python3 -m unittest discover -p 'test_*.py'

The public SPE1 reference is checked in, so the regression suite can compare a run with itself and exercise the first-divergence path without requiring OPM on every machine. The actual OPM path is the command at the top of this page; it records the reference directory and command in the JSON.

Limits you should state

  • The second opinion is an independent reproduction, not the client's original run. It uses this machine's OPM build and stock settings.
  • A divergence is not automatically a defect. It is evidence that two implementations disagree; the first failing cell is where to investigate.
  • The ledger is not a reserves certification. It records a decision and its residual risk; it does not validate geology, upscaling or history match.
  • The ledger hash is tamper-evident, not a signature. Use a signing process when the record must be non-repudiable.
  • Field maps are Cartesian and cell-centred. No corner-point/EGRID geometry, flux vectors or streamlines yet.
  • No client field audit is claimed. The public evidence is SPE1 and the public Norne case; the first client engagement is a pilot.
