How the tools fit together

The products are deliberately separate. Data quality, period close, revenue and compliance are different questions; mixing them into one opaque system would hide the evidence.

01 Check the rows

haql-qc clears missing, negative and contradictory records.

02 Close the period

haql-closeout checks that the month reconciles.

03 Follow the value

haql-revenue reconciles statements and ranks exceptions by dollars.

04 Prove the claim

haql-45q, haql-emission and haql-rrc prepare the evidence.

For an acquisition, haql-dataroom cross-checks the seller's package. For a reservoir forecast, haql-engine explains how the model and its uncertainty are checked.

Common promises

These are the design choices shared across the paid suite. They are also the questions to ask before trusting any output.

Local

Files in, reports out

The paid tools run offline. The data stays on your machine; there is no portal upload, database connection or telemetry.

Deterministic

Same input, same findings

A rule has a stable identifier. The same bytes should produce the same report, which makes a later review possible.

Traceable

Every finding has a source

Reports point to the rule, source row and input fingerprint. Optional signed attestations make later edits detectable.

Advisory by design: a finding is a question with evidence, not an automatic legal, financial or engineering conclusion. The judgement remains with the professional reviewing it.

How to read a guide

Every product guide answers the same questions in the same order: what it does, why it matters, what goes in, what comes out, what it checks, what it does not do, and how to try it. If a claim is not supported, it should not be in the guide.

For the reservoir engine specifically, the public engine guide also explains the evidence and the current scientific limits. The technical reference is there for engineers who want the equations and file map.
